## 1. Compliance Background & Mandate

Under **ADA Title II** regulations for state and local government entities, all public county communications, web documents, news items, and interactive services must meet **WCAG 2.1 Level AA** standards.

To prevent non-compliant content from entering the public space, CMSAdmin 2.0 embeds a live, client-side **Pre-Flight Linter** inside content editors (`pages/edit.cfm` and `articles/edit.cfm`).

---

## 2. Core Rule Groups

The linter evaluates DOM nodes generated by the rich text editor (`JBDEditor`) and surrounding form metadata against 6 distinct rule groups:

### Rule Group 1: Featured Cover Image
- **Rule Citation:** `WCAG 1.1.1 (Non-text Content)`
- **Evaluation:**
  - If a cover image is specified:
    - If `featured_image_decorative` is checked: **PASS** (Technique H67). Screen readers ignore the element (`aria-hidden="true"`, `alt=""`).
    - If NOT decorative and `featured_image_alt` is blank: **CRITICAL ERROR**. Publishing is blocked until alt text is provided or image is marked decorative.
    - If alt text contains file extensions (`.jpg`, `.png`, `.webp`) or generic single words (`"photo"`, `"image"`): **WARNING**.
    - If alt text exceeds 150 characters: **WARNING**. Long descriptions belong in the story caption or extended description field.

### Rule Group 2: Content Body Visuals
- **Rule Citation:** `WCAG 1.1.1 & WCAG 2.4.4`
- **Evaluation:**
  - Embedded `<img>` tags missing the `alt` attribute completely: **CRITICAL ERROR**.
  - `<a><img alt=""></a>` (linked image with empty alt): **CRITICAL ERROR** (unlabelled interactive element).
  - Generic or filename alt text inside body images: **WARNING**.
  - Images with alt text > 150 characters: **WARNING**.

### Rule Group 3: Heading Hierarchy & Document Outline
- **Rule Citation:** `WCAG 1.3.1 (Info and Relationships)`
- **Evaluation:**
  - The page/article title is the sole top-level `<h1>`.
  - Body content using `<h1>` tags: **WARNING** (outline structure). Auto-demoted to `<h2>` via Quick Fix.
  - Empty heading tags (`<h2></h2>`): **CRITICAL ERROR** (produces dead-end audio milestones).
  - Skipped heading levels (e.g. `<h2>` followed directly by `<h4>` without an intermediary `<h3>`): **WARNING**.
  - Top-level section skipping `<h2>` (e.g. content starting at `<h3>`): **WARNING**.

### Rule Group 4: Hyperlink Quality & Destination Safety
- **Rule Citation:** `WCAG 2.4.4 & WCAG 3.2.5`
- **Evaluation:**
  - Completely empty links (`<a></a>`): **CRITICAL ERROR**.
  - Links with placeholder destinations (`href="#"`, `href="javascript:void(0)"`): **WARNING**.
  - Ambiguous anchor text (*"click here"*, *"read more"*, *"more"*, *"link"*, *"download"*): **WARNING**. Screen reader link lists become meaningless out of context.
  - Raw URLs used as link text (e.g. `https://chelancounty.gov/departments/...`): **WARNING**. Assistive technology reads each character.
  - `target="_blank"` without screen reader notification: **WARNING**. Links opening new tabs must append audible notification (e.g. `(opens in a new tab)`).
  - `target="_blank"` missing `rel="noopener noreferrer"`: **WARNING** (reverse tabnabbing security vulnerability).

### Rule Group 5: Data Tables
- **Rule Citation:** `WCAG 1.3.1 (Data Tables)`
- **Evaluation:**
  - Tables with no `<th>` header cells: **CRITICAL ERROR**. Screen readers cannot associate data values with column/row identities.
  - Header cells lacking `scope="col"` or `scope="row"`: **WARNING**.
  - Tables missing a `<caption>` or `aria-label`: **WARNING**.

### Rule Group 6: Readability, Styling & Text Contrast
- **Rule Citation:** `WCAG 1.4.3 (Contrast Minimum) & WCAG 2.4.2`
- **Evaluation:**
  - Document headline empty or < 5 characters: **CRITICAL ERROR**.
  - Hardcoded inline pale text colors (white, #ccc, #eee on light backgrounds): **WARNING** (fails 4.5:1 ratio).
  - Blocks of ALL-CAPS text (>60 characters): **WARNING**. Dyslexic and visually impaired readers struggle with uppercase uniform blocks.
  - Excessive empty spacer paragraphs (`<p>&nbsp;</p>` x3+): **WARNING**. Screen readers read repetitive blank pauses.
  - SEO Meta description > 160 characters: **WARNING**.

## 3. UI Components & Interaction Architecture

1. **Sticky Linter Bar (`.pg-a11y-linter-bar`):**
   - Renders above the editor with an overall badge (`Compliant`, `X Errors`, `X Warnings`).
   - Category chips display counts and highlight errors in red or warnings in amber.
2. **Expandable Audit Diagnostics Drawer (`.pg-a11y-drawer`):**
   - Lists issue cards with exact code snippets, explanations, and remediation advice.
   - Filterable by **All**, **Errors**, and **Warnings**.
   - **Locate in Editor:** Scrolls to the element and runs a CSS pulse animation (`.jbd-a11y-pulse`).
   - **One-Click Quick Fix:** Automatically fixes common infractions (demotes H1 to H2, strips spacers, converts `<td>` to `<th scope="col">`, adds `noopener` and new tab aria labels).
3. **Companion Scorecard Widget (`.pg-a11y-publish-widget`):**
   - Displayed in the sidebar Publish Settings card.
   - Provides live score (`PASS` / `X CRITICAL` / `X WARNINGS`) and direct link to inspect diagnostics.
4. **Pre-Flight Quality Gate in Save Action:**
   - Intercepts save/publish actions when `status === "published"` and `criticalCount > 0`.
   - Prompts author using accessible `window.adminConfirm` modal:
     - Authors can choose to **Review in Drawer** (opens drawer and highlights first violation) or **Publish Anyway** (allows emergency overrides while recording audit state).

## 4. Automated Media OCR & Visual Content Detection (`WCAG 1.1.1 Non-text Content`)

In addition to rich-text linting in Page and Article editors, CMSAdmin 2.0 provides automated **OCR & Visual Content Detection** ([`scripts/crawl-folder-ocr.ps1`](file:///c:/inetpub/CMSAdmin2.0/scripts/crawl-folder-ocr.ps1) and [`api/Files.cfc`](file:///c:/inetpub/CMSAdmin2.0/api/Files.cfc)) for the Media Library:

1. **On-Upload Pre-Flight OCR Auto-Prefill (`/api/Files.cfc?method=analyzeUploadOcr`):**
   - Selecting or dropping an image into the Quick Upload panel (`/media`, `/media/picker`) or Full Upload Studio (`/media/upload`) automatically runs Windows native `Windows.Media.Ocr.OcrEngine` + pixel palette/orientation analysis in the background (~0.6–0.9s).
   - Pre-fills **Alternative Text (WCAG 1.1.1)**, **Display Title**, **Caption**, **Photographer Credit**, and **Tags** before the user submits the upload.
2. **Batch Folder OCR Crawler (`/api/Files.cfc?method=crawlFolder` & `scripts/crawl-folder-ocr.ps1`):**
   - Administrators can feed any workspace folder path via the **OCR Crawl & Auto-Comply Folder** modal in `/media` (or via PowerShell CLI) to recursively scan existing images on disk, extract embedded OCR text, synthesize WCAG 1.1.1 compliant `alt_text`, generate `.thumbs/` previews, and upsert all records into `dbo.media_assets` with `is_wcag_compliant = 1`.
